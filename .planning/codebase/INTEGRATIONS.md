# External Integrations

**Analysis Date:** 2026-08-30

## APIs & External Services

**Aluvia control plane:**
- Aluvia REST API - Provides account data, usage, geo availability, account-connection credentials, routing rules, session IDs, and target geo state.
  - SDK/Client: Internal `AluviaApi` and `requestCore` implementations in `packages/cli/src/net/aluvia-api.ts` and `packages/cli/src/net/request.ts`; there is no third-party API SDK.
  - Base URL: `https://api.aluvia.io/v1` in `packages/cli/src/net/aluvia-api.ts` and `packages/cli/src/proxy-daemon.ts`, overrideable with `ALUVIA_API_BASE_URL`.
  - Endpoints: `GET /account`, `GET /account/usage`, and `GET /geos` in `packages/cli/src/net/aluvia-api.ts`; `GET`, `POST`, and `PATCH /account/connections[/<id>]` in `packages/cli/src/net/config-manager.ts`.
  - Auth: `Authorization: Bearer <API key>` or `X-Aluvia-Install-Id` is attached by `packages/cli/src/net/request.ts`; normal persistence and selection are handled by `packages/cli/src/config.ts` and `packages/cli/src/api-helpers.ts`.

**Authentication service:**
- Aluvia CLI device authorization - Starts and polls a browser-assisted claim flow.
  - SDK/Client: Direct global `fetch` calls in `packages/cli/src/auth.ts`.
  - Endpoints: `POST https://api.aluvia.io/auth/cli/init` and `POST https://api.aluvia.io/auth/cli/poll` in `packages/cli/src/auth.ts`.
  - User callback: `https://dashboard.aluvia.io/cli-auth` is the default claim page in `packages/cli/src/auth.ts`; the API may return a complete verification URI.
  - Auth result: A returned API key is verified through `GET /account`, then written to local configuration by `packages/cli/src/auth.ts` and `packages/cli/src/config.ts`.

**Aluvia data plane:**
- Aluvia proxy gateway - Carries selected Chrome HTTP/HTTPS traffic through an Aluvia residential or mobile exit.
  - SDK/Client: `proxy-chain` via `ProxyServer` in `packages/cli/src/net/proxy-server.ts`.
  - Endpoint: `gateway.aluvia.io:8080` over an HTTP proxy connection by default; host and port are set in `packages/cli/src/proxy-daemon.ts` and `packages/cli/src/net/config-manager.ts`.
  - Auth: Per-connection proxy username and password returned by the account-connections API and converted into an upstream proxy URL in `packages/cli/src/net/proxy-server.ts`.
  - Overrides: `ALUVIA_GATEWAY_HOST` and `ALUVIA_GATEWAY_PORT` are read by `packages/cli/src/proxy-daemon.ts`.

**Public IP detection:**
- IP echo services - Determine whether the tunnel exit differs from the VM datacenter IP.
  - Providers: `https://api.ipify.org/`, `https://ifconfig.me/ip`, and `https://icanhazip.com/` in `packages/cli/src/proxy.ts`.
  - Client: A TLS CONNECT probe through the local proxy is implemented in `packages/cli/src/proxy.ts`.
  - Override: `ALUVIA_PROBE_URL` can replace the default probe list in `packages/cli/src/proxy.ts`.

**Browser and operating system:**
- Chrome/Chromium - The CLI aims browser traffic at the local proxy and optionally restores a requested URL.
  - Process integration: Binary detection, process termination, and detached relaunch are implemented in `packages/cli/src/chrome-launch.ts`.
  - Launch flags: `--proxy-server=http://127.0.0.1:<port>`, `--disable-quic`, and `--restore-last-session` are built in `packages/cli/src/chrome-launch.ts`.
  - Windows policy integration: Chrome proxy policy files are generated by `packages/cli/src/proxy-attach.ts` when launch flags are not the selected attach route.

**Bring-your-own proxy:**
- Custom HTTP/HTTPS upstream - A user can replace Aluvia egress with a pasted proxy URL.
  - Client: URL parsing and storage are implemented in `packages/cli/src/config.ts`; daemon conversion is in `packages/cli/src/proxy-daemon.ts`.
  - Auth: Optional URL username and password are held in local configuration and passed to `proxy-chain` by `packages/cli/src/net/proxy-server.ts`.
  - Constraint: Geo and IP rotation operations reject custom-provider mode in `packages/cli/src/net/config-manager.ts`.

## Data Storage

**Databases:**
- Not detected. No database package, schema, migration, or database connection appears in `package.json`, `packages/cli/package.json`, or `packages/cli/src/`.

**File Storage:**
- Local filesystem only - `packages/cli/src/config.ts` stores durable login/provider configuration in `config.json` and the anonymous trial identity in `install_id`.
- Runtime state - `packages/cli/src/proxy-state.ts` atomically writes daemon, port, connection, session, routing, and attach state to `proxy.json` through a temporary file and rename.
- Default location - `/workspace/.aluvia` when `/workspace` exists, otherwise `~/.aluvia`; `ALUVIA_HOME` can override it in `packages/cli/src/config.ts`.
- Permissions - Configuration directories use mode `0700`; credential and state files use mode `0600` where supported in `packages/cli/src/config.ts` and `packages/cli/src/proxy-state.ts`.
- Agent skill copies - `packages/cli/src/proxy-skill.ts` installs the bundled `skills/aluvia/SKILL.md` into detected agent-specific skill directories.

**Caching:**
- No external cache. `ConfigManager` can hold connection configuration and an ETag in memory, but daemon startup sets polling to disabled in `packages/cli/src/proxy-daemon.ts`; ETag polling support remains implemented in `packages/cli/src/net/config-manager.ts`.

## Authentication & Identity

**Auth Provider:**
- Custom Aluvia authentication.
  - API key mode: A human-provided key is saved by `aluvia auth` through `packages/cli/src/auth.ts` and `packages/cli/src/config.ts` and sent as a bearer token by `packages/cli/src/net/request.ts`.
  - Trial mode: A generated 64-hex install ID from `packages/cli/src/config.ts` is sent in `X-Aluvia-Install-Id` by `packages/cli/src/net/request.ts`.
  - Device flow: Pending device code, user code, claim URL, polling interval, and expiry are persisted locally by `packages/cli/src/auth.ts` and `packages/cli/src/config.ts` until approval.
  - Provider precedence: A stored custom upstream wins, then `ALUVIA_API_KEY` or the stored API key, then the install ID; use `packages/cli/src/api-helpers.ts` as the source of truth.
  - Secret handling: API keys and proxy credentials must not be printed; redaction and public guidance are in `packages/cli/src/net/config-manager.ts`, `README.md`, and `SECURITY.md`.

## Monitoring & Observability

**Error Tracking:**
- None detected. No Sentry, Datadog, OpenTelemetry, or similar package is present in `packages/cli/package.json`.

**Logs:**
- Daemon logs use the local `Logger` abstraction in `packages/cli/src/net/logger.ts`, which writes process-local log messages without an external sink.
- Command results are structured JSON on stdout via `packages/cli/src/cli.ts`; operational guidance treats the `next` field as the next action in `README.md`.
- Sensitive connection configuration is redacted before debug logging in `packages/cli/src/net/config-manager.ts`.
- Readiness evidence and recent CONNECT state are persisted locally in `proxy.json` by `packages/cli/src/proxy-daemon.ts` and `packages/cli/src/proxy-state.ts`.

## CI/CD & Deployment

**Hosting:**
- CLI distribution is configured for the public npm registry as `aluvia-cli` in `packages/cli/package.json`; `publishConfig.access` is `public` and the executable name is `aluvia`.
- The code in this repository does not host the Aluvia API, dashboard, or gateway. Those are remote dependencies referenced from `packages/cli/src/net/aluvia-api.ts`, `packages/cli/src/auth.ts`, and `packages/cli/src/net/config-manager.ts`.

**CI Pipeline:**
- GitHub Actions runs on pushes and pull requests to `main` in `.github/workflows/ci.yml`.
- The CI matrix uses Node.js 18, 20, and 22 and runs `npm ci`, `npm run lint`, `npm run build`, and `npm test` from `.github/workflows/ci.yml`.
- No automated npm publish or deployment workflow is present under `.github/workflows/`; publishing commands remain manual scripts in `package.json`.
- Package preparation synchronizes the canonical skill and compiles the CLI through `packages/cli/scripts/prepack.mjs`.

## Environment Configuration

**Required env vars:**
- None for the supported CLI workflow. `aluvia setup`, `aluvia auth`, and `aluvia proxy-provider` create the local state required by `packages/cli/src/config.ts` and `packages/cli/src/api-helpers.ts`.
- Credential alternatives: `ALUVIA_API_KEY`, `ALUVIA_INSTALL_ID`, or `ALUVIA_UPSTREAM` are consumed by `packages/cli/src/proxy-daemon.ts`; they are process-level overrides and should not be committed.
- Service overrides: `ALUVIA_API_BASE_URL`, `ALUVIA_GATEWAY_HOST`, and `ALUVIA_GATEWAY_PORT` are consumed by `packages/cli/src/api-helpers.ts`, `packages/cli/src/auth.ts`, and `packages/cli/src/proxy-daemon.ts`.
- Local runtime overrides: `ALUVIA_HOME`, `ALUVIA_PROXY_PORT`, `ALUVIA_PROXY_CONTROL_PORT`, `ALUVIA_CHROME`, and other test/diagnostic variables are read in `packages/cli/src/config.ts`, `packages/cli/src/proxy-daemon.ts`, `packages/cli/src/chrome-launch.ts`, and `packages/cli/src/proxy.ts`.

**Secrets location:**
- API keys, BYO proxy URLs, and pending auth state are stored in the local `config.json` managed by `packages/cli/src/config.ts`; proxy credentials returned by Aluvia are held in memory in `packages/cli/src/net/config-manager.ts` and are not written into the repository.
- `.gitignore` excludes `.env`, and `SECURITY.md` requires API keys to be persisted through the CLI rather than committed or printed.
- No repository-owned environment file is present in the scan. Do not add secret values to `.planning/codebase/`, README files, test fixtures, or package configuration.

## Webhooks & Callbacks

**Incoming:**
- No public webhook endpoint. The only inbound services bind to loopback: the Chrome-facing data proxy defaults to `127.0.0.1:18787` in `packages/cli/src/net/proxy-server.ts` and `packages/cli/src/proxy-state.ts`, and the local control server defaults to `127.0.0.1:18788` in `packages/cli/src/proxy-control-server.ts` and `packages/cli/src/proxy-state.ts`.
- The local control server accepts status and lifecycle requests from the CLI only through `packages/cli/src/proxy-control-client.ts`; it is not an internet callback.

**Outgoing:**
- No webhook delivery. All outgoing integration traffic is request/response: REST calls to Aluvia in `packages/cli/src/net/request.ts` and `packages/cli/src/auth.ts`, upstream proxy tunnels in `packages/cli/src/net/proxy-server.ts`, and IP probes in `packages/cli/src/proxy.ts`.
- The human-facing device authorization page is an interactive browser handoff, not a webhook; its claim URL is created in `packages/cli/src/auth.ts`.
